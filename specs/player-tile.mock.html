A mock of the explainer as one object. The title, the cases, the picture, the stepper, the words, the steps, the transcript, the maker's mark and the way out are all inside one tile; outside it the page has only background. The desktop frame is 1180 px wide in an 800 px tall window; the phone frame is 390 px in the dark theme; the third frame is a host article with the tile embedded. Why we put a KV cache in front of D1

Our users endpoint was one D1 query per request. Most of those requests asked for the same few rows, so we added a key-value cache with a five-minute TTL. The change is four added lines and one rewritten; step through it below.

The hit path never touches D1. The miss path reads D1 once, writes the row to KV and replies; the next request for the same user is a hit for the next five minutes.

  1. T4In a frame the page has no padding and no background: the tile's rounded edge is the iframe's edge, and the host's own paper shows at the corners. The host wrote no card around it. The loader passes the host's colour scheme as ?theme= so the frame stays transparent.
  2. T3"Open the explainer" at the end of the footer strip replaces the link the loader used to drop after the iframe, and the one the page used to add at the bottom in a raw iframe.
  3. T6The host knew the height before loading: mr-cache.embed.json publishes it at 390, 640 and 900 px, and mr-cache.oembed.json with a discovery link lets a CMS paste the URL.
