# Blind review of fixed benchmark arithmetic

Scope: read only tools/lib/bench-stats.ts and its comments. No tests, prior review artifacts, executions, or production mutations were used for this pass. Properties below are independently derived; each should own a separate fast-check assertion. “Candidate” means static reasoning, not an executed counterexample.

## Highest-priority contracts

1. **Median finite identity and correctly rounded midpoint.** Surface median. Every nonempty finite array returns a finite value between its order statistics; identical values return that value, including MIN_VALUE, MAX_VALUE and their negatives. Odd-count output is the middle stored sample; even-count output is the mean of middle samples, with appropriate IEEE rounding. Classes: empty (NaN), singleton, odd/even, all equal, permutations, signed zero, opposite signs, cancellation, adjacent representable values, subnormal/normal boundary, both finite extremes. Invalid NaN and infinities anywhere reject, including when outside the middle ranks. Input must remain unchanged after success or rejection. Strong oracle: exact dyadic rational midpoint via decoded floating-point bits and correctly rounded conversion, or mathematical identities on deliberately constructed representable means. Do not use (a+b)/2 as a full-domain oracle: that copies the original overflow defect. Do not use a/2+b/2 universally: that loses subnormals. Current hybrid is plausible; no defect established in it by this read.

2. **Clipped blocking uses task excess interval, not its start membership.** Surface blocking. A task contributes the length of intersection between [start+50,start+duration] and [from,to], floored at zero; tasks of duration<=50 contribute zero. Classes: empty, before-window overlap, wholly inside, wholly outside, left/right clipping, exact boundaries, zero-width window, exact 50 and neighboring values, multiple overlaps. Because wording says “intersect each task”, contributions add even for overlapping task records; do not silently union intervals. Input permutation preserves result mathematically, but floating sum order needs a rounding budget unless representable integral cases are used. Adding records outside the window does not change output. Splitting a window at an interior point makes the two clipped contributions add back to the whole, within justified arithmetic error.

3. **Candidate missed numerical boundary: elapsed durations at very large origins.** The new clipping contract accepts every finite nonnegative time. Absolute endpoint addition can erase or distort the duration in `start + duration` and `start + 50`, even though inputs and expected clipped result are small/finite. Static construction: start=2**53, duration=51, from=start, to=start+100. The written expression rounds start+51 to start+52 and returns 2 instead of the mathematical 1ms excess. Translation of the otherwise identical task/window at origin zero should preserve experienced blocking. This is a candidate numerical contract defect requiring a bounded check; no execution was performed. Decide whether arbitrary finite origins are supported or an elapsed-time magnitude/precision precondition is intended. Do not “fix” its test by imposing a new bound without recording that contract decision. Relative arithmetic can avoid some, but not all, lost input precision.

4. **Window validation is total, including irrelevant records.** Surfaces blocking and longestGap. Invalid finite ordering, negative, NaN and infinite bounds reject even with empty collections. Zero-width and negative zero are valid by current nonnegative policy. Malformed task start/duration rejects even if the task cannot overlap; malformed timestamps reject even outside the window. Bounds and records should be generated independently. Sparse arrays/runtime malformed tuple shapes are not covered by TypeScript's stated typed-domain contract and need an explicit policy before being called bugs.

5. **Longest gap includes both tails and no-frame interval.** Surface longestGap. Independent oracle sorts no input: first validate chronological order, select in-window values, concatenate from and to, then maximum neighboring difference. Empty/all-outside => to-from. One frame => max(t-from,to-t). Frames at either edge add zero intervals. Duplicate frames cannot increase maximum. Adding a chronological in-window frame cannot increase gap. Classes: no frames, singleton, repeated boundaries, one-sided tail, all frames outside, zero-width, maximal finite bounds. Reject descending pairs anywhere, including wholly before/after the window; current whole-trace validation makes this an explicit behavior. Do not impose strict increasing order: equal timestamps are allowed.

## Decisions and invalid observations

6. **Invalid compare data never becomes a decision.** Surface compare. Empty or unequal pair counts throw; NaN/infinite/negative timings or rule values throw, regardless of location, count, or whether the decision would otherwise be unjudged. Generate every rule knob independently; rel and floor zero are valid. Negative zero is currently valid. Keep invalid-batch rejection separate from finite arithmetic laws.

7. **Judgment is independent of observed slowdown.** Surface compare. judged iff valid pair count>=MIN_PAIRS; every valid smaller nonempty batch has regressed=false and judged=false, while retaining real medians/delta/share. Generate 1 through 4, exact 5, 6+, both dramatic regression and improvements. A small stable batch is inconclusive rather than ok at verdict level.

8. **Strict and inclusive thresholds remain distinct.** Surface compare. For judged data, regression is exactly delta>floor AND delta>rel*baseMedian AND slower>=PAIRS. Isolate each condition with independently constructed rank samples; test exact equality at each threshold, next representable difference, exact 7/10 pair share, ties counted as not slower, zero baseline, zero thresholds, all equal, heterogeneous outliers. Large rel*base may overflow although inputs are finite: since nonnegative median delta cannot exceed MAX_VALUE, an infinite relative threshold should correctly prevent regression, not be mistaken for invalid input. Returned delta remains finite for nonnegative finite medians.

9. **Pair-preserving permutations preserve all comparison fields.** Surface compare. Use arbitrary permutations of paired tuples; do not independently permute sides because that changes pairwise slower share legitimately. Duplicate pairs preserve medians and slower ratio but can change judged at MIN_PAIRS, so any replication invariance for regression must keep both counts above the judgment boundary. Translation preserves delta and pairwise comparisons but changes relative baseline; unconditional translation invariance of regression would be an incorrect oracle.

10. **Two-round decision table with insufficient batches.** Surface verdict using comparisons produced by compare. If either supplied comparison is unjudged, result is inconclusive. Otherwise first nonregressed => ok, first regressed plus absent second => not reproduced, first regressed plus judged nonregressed second => not reproduced, and both judged/regressed => regression. Generate every truth-table cell. Particularly easy to miss: judged first nonregressed plus explicitly supplied unjudged second is inconclusive under current precedence, not ok. Comments only explain reproduction, so document that precedence if intentional. Missing second after judged regression remains not reproduced rather than inconclusive; that is the current distinct policy. This must be made explicit rather than inferred from the type union.

11. **Comparison is structurally constructible.** verdict publicly accepts Comparison, whose type does not forbid judged=false/regressed=true or NaN fields. Its decision uses only two booleans. Do not invent rejection of forged inconsistent objects unless the contract is strengthened; generate verdict inputs from compare for domain-level guarantees, and test the boolean table separately if desired. Two separate measurement rounds are a caller obligation: the pure helper cannot prove rounds were independently collected.

12. **Alternating order.** Surface order. For nonnegative integer repetition indices, every returned tuple contains exactly base/head once, even starts base and odd starts head; neighboring repetitions reverse. Empty/malformed/noninteger repetitions have no stated meaning. Large integers beyond exact parity representation are not distinct JavaScript repetition indices; avoid an oracle that assumes unavailable integer precision.

## Additional numerical policy worth stating

- blocking sums contributions per record. Many individually finite contributions can overflow the total, even though each window is finite. The comment does not promise finite output or reject overlapping/impossible main-thread records. Decide whether output Infinity is accepted or the trace domain must prohibit such records before demanding a finite-result property.
- Math operations on finite timestamps have rounding error. Exact endpoint identities and zero-width/no-frame results need no arbitrary epsilon; partition/translation relations at very large magnitudes need an independently justified numeric contract. Property generators must include these classes rather than hiding them after failure.
- No documented complexity bound stronger than the obvious pass/sort model appears here. Useful bounded probes can count that input validation considers all records, verify large empty/outside windows, and compare N/2N materialized trace workloads. Do not demand logarithmic frame lookup or constant-time median without a promised contract.

Recommended next actions: confirm candidate #3 with one bounded standalone example; add/retain full-finite median identities and an independent midpoint oracle; explicitly document verdict precedence for missing versus insufficient second measurement. No existing tests were inspected to assess whether these are already covered.
