## Observed validator boundary candidate — separate finding, not yet a repaired defect

A narrow, in-memory probe cloned the committed Arabic snapshot, chose a nonempty run, set the first glyph's cluster to the source code-point count, and called `validateLetteringSnapshot`. The validator accepted `text='السَّلَامُ عَلَيْكُمْ'`, `cluster=21`, `sourceCodePoints=21`. No file, source or production state was modified.

Evidence: `src/lettering-outlines.ts:25` says clusters count source code points, including RTL. `tools/lettering.py` writes `cluster=chars[info.cluster]['index']`, where source `index` comes from `enumerate(text)` and therefore lies in `[0, len(text))`. `test/lettering/oracle.py` explicitly passes code points to HB. The JS span adapter maps those code-point clusters into UTF-16 offsets with `form.source[g.cluster]`; a one-past cluster falls back to `text.text.length`, which can corrupt source selection/matching despite finite geometry. `tools/lib/lettering-validation.ts:28` rejects `cluster > [...text].length`, permitting equality.

No source evidence supports equality as an advance/caret sentinel. Carets are computed by CodeSpan from source positions, not represented as extra stored glyphs. Zero-width combining marks still carry their base cluster; controls carry their own actual source index. Empty input from HB has no glyphs; mathematical rule glyphs use cluster0 for nonempty TeX strings, and `gid=-1` is the rule sentinel, not an extra source cluster. However, validate a real cached-project flow with fresh metadata and a recomputed payload hash before changing this bound: the direct acceptance probe does not yet prove the complete public build path. Exercise empty strings, nonempty math/rule runs, Cc/Cf controls, astral source characters and combining clusters in that control. Do not rewrite snapshot provenance or weaken a fingerprint to reach the guard.

## Cheaper PBT candidates, grounded in real owners

- **Serialized snapshot schema** (`validateLetteringSnapshot`, caller `prepareLettering`): separate valid-accept and invalid-reject properties over run-key tuples, finite metrics, scale positivity, integer glyph IDs/clusters, source bounds, all five outline commands and face-data encoding. Use honest structural fixtures and distinguish schema validity from actual font decode validity. Near-valid corruptions must hit the intended structural diagnostic even when the payload checksum is recomputed. Capture/Node/project controls remain one real boundary fixture; thousands of schema cases need no Python or browser. Test the observed one-past cluster explicitly after confirming its semantics.
- **Closed-world provider selection/scaling** (`snapshotProvider`, `scaledRun`, callers Text/Math and capture): generate both sans/mono families, captured strings versus unrecorded prose, display keys and nontrivial positive sizes. Pin the selected stored run and rendered scale; assert source snapshot immutability. Reject changed wrappers and unrequested strings, not merely no crashes. Avoid asserting floating-point associativity; identity scale and exact lookup selection are exact, while renderer-coordinate tolerance needs a representation-derived rationale.
- **Numeric replay**: generate FPS/materialized frame counts, finite formatted numbers, decimals and prefix/suffix wrappers across both font families. Preserve literal Greek and explicit/implicit-face regression rows. The rich input space is strings/configuration, so do not replace current high-value value oracles with `isNumericText` tautologies. Shape results must agree with the chosen original source-face chain, and arbitrary changed prose must still reject. Bound materialized frames, not the semantic numeric domain; one large-cache probe can cross the4096 replay memo threshold without thousands of full scene captures.
- **Request/routing** (`letteringRequest`, `validateLettering`, `usesOutlineLettering`, caller collectProject): test valid legacy-only requests and outline requests, field presence versus false values, invalid objects/keys/types/scripts/faces and duplicate simple-script requests. Current legacy parser test accurately checks that old helper but its title overstates product rejection: the product supports Arab/math by a different route. Fix the title and retain old-parser contract. Never infer whole-product unsupported status from a helper the dispatcher bypasses.
- **Math adapter**: preserve the HB symbol source oracle, then pin actual positions, rule rectangles, scales and display mode against the direct glyph typesetter output. Current presence/shape-count assertions do not establish layout. Public siblings `Math`/`MathTex`, constructor display false/true, setText, copy and transform/seek need explicit coverage or a stated reason. PR25 is actively addressing maths faults; reconcile its keeper before adding another competing harness. Testing the entire upstream TeX implementation is not Rayner's owner; testing Rayner's layout translation is.

A browser benchmark's latency, frame scheduling, layout and paint are not equivalent to any of these data properties. Keep one qualified browser measurement for those effects. PBT is the cheap primary proof for pure arithmetic, validation, source mapping and decision logic; it cannot assert a real browser meets a millisecond budget.
