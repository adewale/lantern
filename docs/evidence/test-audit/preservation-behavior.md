# Independent preservation review: View and engine behavior

Reviewed working-tree changes against origin/main in src/view.ts, test/view.test.ts, test/emphasis.test.ts, test/explain-emphasis.test.ts, test/matching-motion.test.ts, and test/scene-hooks.property.test.ts, together with relevant Mobject/Animation/Scene implementation and View documentation. Static review only: no commands executed tests or mutants; no production/test edits.

## Findings

**No blocking correctness or preservation defect found in the reviewed diff.** The View change restores only bookkeeping for a discarded target, and the test changes preserve the prior asserted contracts. Two nonblocking limits deserve explicit treatment:

1. **Regression exercises endpoint zero, not an actual returning excursion.** `test/view.test.ts` uses `rateFunc: () => 0` and `back.interpolate(0)`. This correctly reproduces the bookkeeping bug and verifies both public follow-up paths (rebuild and sync); it does not demonstrate returning from an interior alpha. Smallest useful extension: interpolate an interior value before finish, using a rate function ending zero. This would catch an accidental dependence on current geometry while restoring the scale basis. This is an additional coverage observation, not an incorrect existing assertion.

2. **Partial terminal alpha is included by the implementation branch but not the new regression.** `src/view.ts` restores previousSize/previousScale for every terminal value other than 1. For terminal zero this unambiguously restores the retained picture's original construction basis. At a partial terminal alpha the retained object has interpolated geometry, so the next fit measures that geometry relative to its prior build. This follows the existing retained-object behavior; the patch does not restore points or text and should not be described as making arbitrary partial endpoints identical to the old picture. A targeted partial-endpoint regression would clarify this lifecycle contract, but there is no demonstrated new failure in the change.

## Production preservation analysis

- begin saves `builtSize` before fit overwrites it and saves `scaleK` before fit may recompute it. `builtSize` is replaced with a fresh size tuple by fit, not mutated in place, so retaining the old tuple reference is sufficient.
- Terminal zero: inner interpolation restores source geometry; retained child identity is unchanged; original construction size and scale estimate are restored. A subsequent public rebuild or sync can infer scale from the correct source dimensions. Restoring previousScale rather than the newly measured one is safe because the next fit measures current dimensions again when it has a nondegenerate axis; fallback behavior on a degenerate old picture is preserved.
- Terminal one: target is swapped in and its new builtSize/scaleK remain in effect. Child/parent handoff is unchanged.
- No-op: finish still exits immediately; fit bookkeeping remains as before, and no child is replaced. This diff does not alter no-op semantics. In exact same-picture cases current geometry matches the fitted target and the updated basis is appropriate; tolerance-level differences remain the previously documented 1e-5 no-op policy.
- Partial terminal value: child retention and interpolated geometry remain the old behavior. Restoring the original build basis makes the retained object's measurement refer to its own build rather than a discarded target; it does not introduce a geometry reset.
- `View.scale` remains inherited directly from Mobject.scale/applyAffine. The patch adds no override, affine side effects, updater, scaling cache, copy behavior, or scene lifecycle operation. Public scale still modifies the current family's points; fit still measures that result. No new production hook was introduced.
- A thrown builder or fit can still leave a partially begun animation, but the diff does not change its exception policy. begin/finish reuse and out-of-order lifecycle calls have no new public guarantee.

## Test preservation analysis

- **Succession/public callback:** replacing a global ViewSync.prototype.begin monkeypatch with the builder callback strengthens public observation. It asserts construction builds only once, sync construction is lazy, first member observes the state changed before play, second observes intervening Mutate state, and the final current Text has the right content. Original Ring coverage remains elsewhere in the file. No loss of the prior lazy-begin contract was identified.
- **Circumscribe mode oracle:** at alpha 5/6, the default fade path should be fully drawn with lowered opacity while retract mode remains at its captured 0.8 opacity with a partial path. Assertions distinguish the two documented modes through public outline styles rather than only absence of verifier events. They do not assume a particular easing value beyond its range. Existing variants/finish/motion tests remain untouched.
- **Absent heading:** the new case checks both empty heading text and absence of the step title from the scene's Text family. That matches heading:false and does not remove fixed-heading or following-title coverage. It deliberately does not assert the helper object is absent entirely; retaining an empty helper object is allowed.
- **Broader lag:** the existing gentle-lag motion property and its generator remain unchanged; its new name accurately states the existing bound. The new [0,1] lag replay property adds deterministic seek agreement without falsely demanding no motion spikes for the larger domain. Generated frame k is in [0,36], exactly initial frame plus 30 animation frames plus six wait frames at default 30fps. Both runs use the same generated Morph and overridden lag. StringSink full.frames[k] is an appropriate concrete oracle for SnapshotSink renderAt. Large-lag replay coverage does not establish smoothness, nor does it claim to.
- **Skipped caption timing:** changing helper default to Infinity avoids rendering in arithmetic properties but does not remove their timer/hold oracles. Crucially, the parity property now explicitly calls run(p,0) and run(p,Infinity), preserving genuine full-play versus skipped execution after the helper-default change; the trace property still compares a skipped helper run against traceScene's separate actual run. All previous assertions and generated plans are retained. These properties concern time boundaries, not rendered pictures, so skipped helper execution is appropriate.

## Conclusion

Accept the reviewed preservation changes. Suggested returning-excursion and partial-endpoint cases are useful follow-ups, not evidence that the current regression or production fix is wrong. Validation in this review was read-only static inspection; execution evidence must come from the parent task's check results.
