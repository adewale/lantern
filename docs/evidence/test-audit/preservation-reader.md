## Finding requiring repair

**P2 — The caption-layout loop no longer proves that each requested caption was displayed.** `test/explain-embed.test.ts:236`–239 removes the old assertion that button i has aria-current=step and waits only for any new rayner:step event. A wrong navigation implementation that repeatedly shows step zero can still emit an event for each click and leave every measured top identical. The test would then pass without exercising all caption heights, its intended contract. Keep the stronger event/RAF synchronization, but also require the target button current state after settlement; preferably record/match event detail.step to the clicked button data-step. The real implementation in app/embed.ts:338–360 correctly selects and settles its requested step; this is a test-preservation gap, not an observed product defect. General browser navigation checks remain, but cannot make this particular across-captions proof nonvacuous for its exgit/mr-cache/send-sync fixtures.
