# Independent preservation review: authoring lane

Reviewed the seven changed authoring test files against origin/main, their retained neighboring assertions and relevant production contracts. I did not author these changes. This review made no test/production edits, executed no tests and applied no mutations. Findings are based on source and diff inspection, not fresh runtime evidence.

## Finding: valid narrow/default Card state transitions lost coverage (medium)

`test/explain-panels.property.test.ts:358–361` maps every strict positive Card case to explicit width>=2, widens every box to>=2 and converts region names to boxes. All stateful set/unknown-row/fade/mark properties now consume that mapped domain. Original `cardCase` generates widths1.2..12, optional width, optional/named/box/point placement and font sizes.08...5. Before the change those original cases exercised stateful behavior whenever construction succeeded.

There are supported accepted cards below2: `explain/panels.ts:138–140` requires width>=.56+2.5*fontSize. At fontSize.08 this is.76, so explicit width1.2 or a1.2-wide box is valid. Current stateful generators no longer construct such cards. Similarly the default natural-width constructor branch no longer reaches set/mark/fade properties, since fittingCardCase always provides width. The new broad-domain property at :364–373 restores construction acceptance/refusal and initial rowsInside only; it does not restore post-set containment, stale-value removal, unknown-row atomicity, opacity inheritance or marking at narrow/default sizes. A width<2-specific stale-value or overflow mutant would have lost its stateful keeper.

Required repair before calling the domain preserved: create guaranteed-fitting cases by lifting only invalid widths/box caps to the actual per-case threshold plus a small justified safety margin; leave already-valid widths, omitted defaults and region spellings untouched. Alternatively retain the original broad-domain stateful properties alongside the new guaranteed-positive tests. Keep explicit rejection generation below the actual threshold. This is a generator-coverage issue rather than evidence of a product defect.

## Re-review addendum: per-case threshold revision

Read the revised generator after the author reported26 passing panel tests; I did not rerun them. The new minimum `.56 + 2.5*fontSize + EPS` restores accepted widths1.2..<2 whenever they exceed that sample's minimum, so the blanket2-unit loss is repaired. A tiny EPS boundary band is deliberately lifted for fitting construction.

The original finding is only partially resolved: the revised `at` expression still converts every named region into its Box, and the returned object still always supplies `width: Math.max(minimum, c.width ?? 3.2)`. Thus default natural-width and named-region input spellings still cannot reach stateful properties, despite the requested preservation. Broad original construction coverage remains, but it does not prove these stateful branches. Preserve undefined width and unchanged named regions; lift only defined insufficient widths and explicit insufficient box caps (with a fresh copied Box), or retain the original broad stateful keeper. No assertion of complete default/named preservation can be made from the current source.
