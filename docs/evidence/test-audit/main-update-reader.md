## Source/domain findings

1. **Thin positive overlaps are a concrete specification mismatch candidate, not yet executed.** `stressStarts` docs say a box with area inside a part contributes a start, while mere touching does not. The code requires overlap side >1e-6 for a nondegenerate stress side. For stress `[0,0,1,1]` and part `[0.9999995,0,2,1]`, intersection has positive width 0.0000005 and height 1; code excludes it. The new property skips every intersection side <=1e-3, so it cannot expose this. Conversely a stress box with a positive side <1e-6 is treated as a zero-width line when touching. Resolve the intended numeric/degenerate contract explicitly; do not exclude these valid boxes to force green.
2. Existing prioritization property is a shared-oracle survivor risk: stressStarts returning [] can satisfy ordering. The independent completeness owner catches broad deletion on ordinary large boxes, but isolated boundary omissions and stable group order still need stronger direct proof.
3. `emphasisOf` merges multiple descriptors on one object, and fresh emphasis compares current descriptors to previous step-end descriptors. Existing new integration covers Card/Code focus state changes, not all announced marked/travelled/focused Diagram, notes, diff lines, clipping and opacity. Producers return object identity + state token; actual visible-leaf capture should keep hidden/detached/clipped marks from creating stress. Add bounded direct integration only for these separate producer contracts; don't replace real producer scenes with a test-only fake provider.
4. Close-ups are now selected using their actual clamped boxes before choosing opening/priority. Keep the audit's union coverage and lead-containment laws over arbitrary aspect ratios and stress. These provide independent invariants for the changed algorithm rather than assuming a reorder must be correct.
