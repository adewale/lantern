# Blind adversarial contract properties

Read implementation and named contract documentation only; no current tests, audit plans, or ledgers were read. References to test filenames encountered inside implementation/documentation were not followed. Priorities rank properties by likely actionable defects and independent oracle strength. Each numbered item should become a separate property, rather than a combined test. Numeric geometry comparisons must account only for the documented Float32 representation; exact endpoint and identity claims remain exact.

## P0: demonstrated bounded counterexamples

1. **IPv4 /0 includes every valid IPv4 address.** Public surface: `inRange(addr, range)` in `scenes/explainers/lib/trust-proxy.ts`. Contract: “proxy-addr's range test for IPv4: an address, or address/prefix”; model excludes IPv6, not IPv4 /0. Standalone Node 24 strip-types execution returned `inRange('203.0.113.7', '0.0.0.0/0') === false`; standard CIDR requires true. Generate prefixes 0–32, network host bits set and clear, first/last address of subnet, and one address immediately outside when one exists. /0 is the maximal network; /32 the singleton. Ground network membership in unsigned integer division, not the implementation's bit shifts.

2. **Malformed CIDR does not silently become a valid range.** Same surface and contract. Actual bounded execution returned true for both `inRange('10.255.0.1', '10.0.0.0/8.5')` and `inRange('10.0.0.1', '10.0.0.0/8/garbage')`. A prefix is an integer and a CIDR has one slash. Generate fractional, signed, missing, whitespace-only, infinite, >32 and negative prefixes; extra slash components; missing octets; >255 octets. Existing return-false validation suggests rejection rather than acceptance, but exact throw-versus-false policy is not documented and should be settled explicitly. Do not exclude malformed classes merely because acceptance is found.

3. **Median of identical finite samples is that sample.** Public surface: `median(xs)` in the benchmark original module. Contract: “Middle value; the mean of the two middle ones for an even count.” Actual execution: `median([Number.MAX_VALUE, Number.MAX_VALUE])` was Infinity (JSON prints null). The mathematical median is Number.MAX_VALUE exactly. Generate empty (NaN), singleton, repeated values, even/odd lengths, both signs, signed zero, subnormals, near-maximal finite values. This is a named numerical contract, not a demand that benchmark clocks reach extreme values. Separate properties: permutation invariance and input immutability.

Reproduce the above without any test imports:

```sh
node --experimental-strip-types --input-type=module -e "import {inRange} from './scenes/explainers/lib/trust-proxy.ts'; import {median} from './out/test-audit/bench-original/tools/lib/bench-stats.ts'; console.log(inRange('203.0.113.7','0.0.0.0/0'), inRange('10.255.0.1','10.0.0.0/8.5'), inRange('10.0.0.1','10.0.0.0/8/garbage'), median([Number.MAX_VALUE,Number.MAX_VALUE]));"
```

## P1: windows and decision arithmetic

4. `blocking(tasks, from, to)`: exactly the sum of duration above 50 for tasks whose **start** lies in inclusive `[from,to]`. Contract explicitly chooses start inclusion, so a task starting before the window contributes nothing even if it overlaps it; a task starting at `to` contributes its entire excess, not clipped excess. Classes: empty, duration 0/50/just over 50, singleton window, boundary starts and their adjacent representable numbers, overlapping tasks, reversed window. Negative/nonfinite durations and unsorted tasks should be classified explicitly; malformed duration NaN currently poisons the sum, but no rejection contract is stated.

5. `longestGap(frames,from,to)`: maximum consecutive frame wait with initial predecessor `from`, using frames inside the inclusive window. Empty and all-outside windows give 0 under the currently described initial-to-first rule; a tail from final frame to `to` is not explicitly promised. Generate ascending timestamps, duplicate frames, exact boundaries, no frame after from, one frame, sparse clusters. An important contract clarification: implementation stops at first `t>to`, but its public comment does not state sorted-input requirement. Either document chronology or test permutation invariance and fix the implementation; do not silently narrow the generator to sorted inputs without recording this precondition.

6. `compare(base,head,rule)`: exact decision conjunction: equal nonempty pair counts; at least MIN_PAIRS; median delta **strictly greater** than absolute floor and relative baseline; pair slower share **at least** PAIRS. Independently vary every knob and separate each conjunct in a property. Classes: 0/1/4/5 pairs, ties, exact thresholds, 7/10 slower, paired permutations versus independent permutations, zero baseline, heterogeneous outliers. Check returned medians/delta/slower values, not only regressed. Unequal and empty arrays must throw. Finite nonnegative clock samples and finite nonnegative rule values are the meaningful measurement domain; malformed nonfinite or negative values require an explicit policy before asserting one.

7. `verdict(first,again)`: first nonregressed always yields ok; first regressed with absent/nonregressed second yields not reproduced; two regressed yields regression. Generate unrelated Comparison fields so those fields cannot accidentally influence verdict. `order(rep)` alternates for nonnegative integer repetitions, and each tuple contains each build exactly once; fractional/nonfinite reps have no documented repetition meaning.

## P1: path geometry

8. `VMobject.pointOnCurve(i,c,t)` has exact stored anchors at t=0 and t=1; `pointFromProportion(0/1)` has exact first/last path endpoints. Contract explicitly says the ends are exact. Generate finite Float32 coordinates including negative zero, tiny/large magnitudes, multiple subpaths and degenerate endpoint curves. Avoid NaN/infinite geometry when asserting finite arithmetic laws. Single-point subpaths before/after drawable subpaths expose an ambiguity: “path's own first and last points” versus first/last **curve**; clarify before excluding these valid builders.

9. `VMobject.pointFromProportion(t)` on a zero-length path answers its first point for every t, as documented. Generate multiple disconnected degenerate curves at different coordinates, singleton/no-curve paths, and t=0/1/interior/outside/NaN. Particularly challenge t=1: implementation handles endpoint before zero-total fallback, so distinct zero-length subpaths may return the last subpath point against the zero-length contract. This is a strong candidate counterexample, not executed here because importing VMobject also loads project dependencies.

10. `arcLength()` agrees with the sum of `curveLength(i,c)` in traversal order and excludes jumps between disconnected subpaths. Grounding: both promise the same eight-sample polyline. Construct independent eight-segment numeric oracle from cubic Bernstein evaluation; cover empty, singleton, all-zero, cusp, loops with zero chord, straight unequal-length curves and disconnected paths. Do not compare with analytic arc length as if approximation were a bug.

11. `VMobject.splitCurve(a,c,parts)` preserves exact first/last stored anchors and yields `oldCurveCount + parts-1`; interior evaluation of piece j at u agrees with original curve at `(j+u)/parts` to justified Float32 rounding. Contract explicitly equal parameter spans via de Casteljau. Classes: parts=1, 2, larger integer; first/middle/last curve; zero-length and zero-chord loops. Invalid parts 0/fractional/negative/nonfinite have no defined policy; test rejection only after documenting it.

12. `insertNCurves(i,n)` increases count by n while preserving path geometry, endpoints, closure, untouched subpaths, and lone-point location. Separate geometry preservation from the Manim allocation oracle: count/shape alone cannot establish the named allocation rule. Cover n=0/1, lone point, zero-length markers, equal chords, highly unequal chords, loops whose handles create length but chord is zero. `alignData(other)` equalizes both structures without moving either geometry; empty versus nonempty and unequal subpath counts are critical.

## P1: reader camera and viewport

13. `clampZoom(z,w,h,max)` is idempotent and covers each finite nonnegative stage: `1<=k<=max`, x/y<=0, `x+w*k>=w`, `y+h*k>=h`; k=1 implies x=y=0. Contract states coverage explicitly. Generate zero/tiny/large stage sides, max=1 and >=1, all boundary pans, adjacent representable bounds, NaN components and infinities. Invalid max<1 or dimensions<0 need an explicit precondition. Test coverage with the same actual arithmetic the renderer uses, not a widened epsilon.

14. `zoomAt` with factor=1, or saturated zoom in the saturation direction, equals clamped input exactly. Interior zoom preserves the selected world point when the resulting pan needs no clamp. `panBy` with zero deltas is identity after clamping; a NaN delta leaves its own axis unchanged. Evidence: individual doc comments and explicit no-creep comment. Classes: identity/max zoom, edge and center anchors, NaN factor, infinite pointer coordinates, tiny changes, extreme finite factors; distinguish clamping from failure to anchor.

15. `readerViewBox(author,IDENTITY,w,h)` returns the author string byte-for-byte, including comma/whitespace forms; nonpositive stage width or height returns it unchanged. Nonidentity result must project the same world points as fitted author's view followed by stage-space scale/pan, using SVG letterbox offsets. Evidence: readerViewBox/fitted comments and docs/REFERENCE.md reader zoom description. Generate landscape/portrait/square stages and cameras of mismatching aspect ratio, nonzero/negative camera origins, zoom limits and border pans. `zoomOfView(author,readerViewBox(...))` recovers z within the documented 0.001 user-unit quantization propagated through the inverse, not arbitrary epsilon; exact string identity returns exact identity. Malformed author strings, missing/zero sizes, NaN and infinity need explicit validity policy.

16. `cameraOf`, `ReaderView.paint`, and `ReaderSink.apply`: first camera capture is stable; reader paint never overwrites author's data-camera; each camera update remains current under ongoing reader glide; reset/Fit paints author's latest frame. Generate preexisting/missing data-camera, missing viewBox, svg inserted late, changing author frames, empty element arrays, interrupted glide and reduced motion. Control RAF timestamps so endpoint at 220ms is exact and cancelled glides cannot repaint later. Public DOM assertions should check viewBox/data-camera writes and resulting values, not private fields. Stage resize via `StageZoom.apply` must preserve normalized pan (subject to clamp), including repeated resize, zero-size then visible, `to()` before resize, and reset.

## P1: graph and coordinate equivalences

17. `NumberLine.n2p` maps min/max to current line endpoints; `p2n(n2p(x))` recovers x and extrapolates, before and after translation/rotation/uniform scale. `Axes.p2c(c2p(x,y))` is the inverse under nonsingular rotation/shear, not merely default axes. Evidence: method comments, especially p2c's explicit shear claim. Generate ranges excluding zero, asymmetric signs, unequal axis scales, off-range points, tiny nonzero determinant, and independent affine transformation. Exact endpoints should be checked separately from approximate inverse arithmetic. Singular axes have no documented inverse.

18. `Axes.plot` anchors equal Float32-rounded c2p(sample,fn(sample)); each segment is bounded by neighboring sampled y values when decoded back into data coordinates; constant plateaus stay constant. Evidence docs/GRAPHING.md Plot. Generate two samples, long runs, unequal spacing by subrange, steep sign changes, plateaus and extrema. Nonfinite fn values split runs and must never be bridged; empty finite runs and isolated finite samples produce no drawable segment. Assert each subpath's sample adjacency rather than only subpath count. samples near 2, fractional, zero/negative and NaN/infinite are configuration boundary classes; only finite rounding/clamp behavior is evidenced by code, with no documented nonfinite-input policy.

19. `Axes.bar` zero, positive and negative values retain the same ordered closed geometry, with data-space baseline exactly y=0 and top y=value; equal-size sets interpolated by index keep baseline fixed and top moves linearly through zero. Evidence docs/GRAPHING.md Bars and bar comment. Generate empty/single/many values, zero/sign flips, custom x/width/gap, colors array, shifted/rotated axes, explicit labels. `lineGraph` preserves input order including repeated points; `areaUnder` closes on y=0. These are distinct properties.

## P1: timing and View lifecycle

20. Scene's clock always equals frameCount/fps; first sink frame has dt=0; subsequent rendered frames use 1/fps; waits and plays finish on their declared quantized frame count. Evidence scene.ts fixed-frame comments and tick. Generate fractional positive fps, zero/short/nonintegral durations, repeated mixed waits/plays, empty plays (clarify intended semantics), skipUntil immediately before/on/after frame boundaries. Invalid fps 0/negative/nonfinite may hang or produce invalid clocks and needs rejection policy rather than unbounded execution.

21. Full-run and skipped-run snapshots at the same emitted frame agree, including camera, View child/text/style, state, evidence and timing. Evidence scene.ts skip contract and docs/VIEWS.md byte-identical seek claim. Generate changed/unchanged sync, nested Succession, camera updater and mobject updater appearing mid-sequence, rate function returning to zero, mixed runtimes. Updater integration must not be skipped, and camera updater runs after object updater. Each aspect should be isolated into its own property.

22. `View.sync` calls build at begin, not sync creation; changed terminal sync replaces only child and preserves View identity/parent; old child is detached. Unchanged picture keeps exact child identity yet consumes equal runtime. Evidence View comments and docs/VIEWS.md. Generate all match variants, nested/empty Groups, different styles with same geometry, changed text with same glyph shapes, fresh equal pictures, state mutated between sync creation/begin, rate functions ending 0 versus 1. Invalid fresh builds (non-Mobject, already parented, current object) must reject.

23. View placement preserves requested layout anchor and inherited uniform scale across repeated sync/rebuild; false placement uses builder coordinates. Evidence docs/VIEWS.md Placement; Text uses advance box. Generate left/center/right/false, empty-to-nonempty and reverse, flat paths, zero width/height, explicit moves/scales and changed builder dimensions. A particularly adversarial sequence is a returning rateFunc followed by another sync: `fit()` mutates builtSize before failed-to-land sync finishes, so scale bookkeeping may describe the unadopted picture. Check subsequent scale against original builder dimensions; do not inspect private state as the oracle.

24. `Scene.onStep` duplicate callback registrations remove independently; removed listeners in an in-progress dispatch do not run; newly added listeners first hear next step. `StopScene` from frame/stepBegin/stepEnd permanently prevents subsequent play/wait/step/emitFrame effects even when caught. Evidence explicit registration and stopped contracts. Generate self-removal, removal of a later listener, duplicate function values, async listeners, nested registration, stop at every sink entry, repeated removers.

25. `perf.span` preserves return value and exception identity while balancing stack, and parent self time excludes synchronous children exactly under a controlled clock. `perf.begin` supports sequential async operation only; its own comment excludes nested-across-await self guarantees. Generate disabled/enabled, thrown inner/outer callbacks, repeated names, timelineDepth 0/1/2 and counters with arbitrary names. Clarify whether end callbacks are one-shot: calling end twice currently records twice but idempotence is not promised. Scene.emitFrame opens perf.begin('sink') without finally, so a rejecting sink may leave an open span; a bounded rejection probe should verify whether subsequent measurements are contaminated.

## Scale probes with grounded expectations

- VMobject arcLength/curveLength explicitly use eight samples per curve: count pointOnCurve evaluations for N versus 2N curves to establish linear work without wall-clock flakiness. Public method override in a standalone subclass is sufficient; no production hook needed. pointFromProportion similarly measures every curve; do not demand logarithmic lookup that is not promised.
- Graph plot contract requires one sample callback per sampled x and one cubic per finite neighboring pair. Count function calls and resulting anchors at increasing materialized n; nonfinite segmentation must not add calls. No general O(n) constructor claim is documented: addCubic repeatedly copies arrays, so do not invent a passing linear-time budget. A wall-clock N/2N/4N probe can expose quadratic growth as a performance finding, with no unsupported assertion.
- perf promises only spans through timelineDepth become events, deeper spans aggregate to keep a 700-frame trace small. For fixed depth cap and increasingly deep synchronous nesting, event count depends on retained levels, not total depth; rows/counters must still aggregate all calls. Test event counts via public chromeTrace output.
- View documentation promises endpoint construction instead of per-frame rebuilding: at varied fps/runtime, build count is construction plus each sync begin, independent of frame count. Record builder calls, preserving no-op runtime. Scene skipped seeks should emit only the necessary suffix when no updaters exist; add an updater to verify the documented exception.

Resource bounds belong at materialization: draw broad valid counts/configurations, then classify or truncate a standalone probe's constructed workload with the limit recorded. Never reinterpret a discovered valid failing input as invalid merely to make a property pass.
