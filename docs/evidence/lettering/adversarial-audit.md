# Adversarial review of PR #14

Five reviewers independently examined runtime behavior, Unicode shaping, capture
and freshness, installed-package behavior, and the cost guarantee. Findings were
reproduced against the actual PR implementation, then checked again after fixes.
The PR was integrated with main at `fe99d1ea9f90b4f76dafd6fc9c7511b3ac40a597`.

| Finding | Resolution and regression evidence |
| --- | --- |
| Replacement-font counters captured endpoints and crashed on intermediate values or another video FPS | Replay a bounded numeric alphabet and known numeric templates through the existing shaper with stored subsets; test negative/fractional values, static wrappers, implicit Greek families, seeks and several FPS values |
| Installed CLI rejected checkout-captured snapshots as stale | Canonicalize outline engine imports across `src/*.ts` and `dist/src/*.js`; archive smoke checks/builds all four fixtures with Python and source fonts unavailable |
| Legacy bidi put following numbers inside mixed-direction brackets | Use validated resolved levels from the pinned modern backend, retaining original source indices; independent bracket/mirroring and astral-index regressions |
| Script defaults overrode explicit faces and mono text | Prefer the explicitly requested face when it covers a cluster; preserve existing mono coverage and fall back by complete base/mark clusters |
| RTL code-span boxes covered the wrong visual cells | Optional adapter maps logical source ranges to visual cells, including empty carets, partial clusters, copied lines and queries after scene completion |
| Contact-sheet headings silently lost requested lettering | Capture numbered titles and draw them within the scene's font lease |
| Joiners/control characters lost shaping semantics or failed capture | Preserve ZWJ/ZWNJ through HarfBuzz, paragraph boundaries and supported blank control advances; compare with direct HarfBuzz |
| Cached outline corruption and embedded-font changes escaped freshness checks | Validate finite run/path structure, verify a payload checksum and fingerprint embedded fonts/core shaping inputs |
| Same-provider nested work could deadlock or outlive its font lease | Reentrant same-provider tasks share the lease and drain before restoration; independent ordinary renders remain isolated |

The new regressions are in `test/lettering-{runtime,pipeline,unicode,integration}-audit.test.ts`
and `test/lettering/unicode_audit.py`. CI runs the optional capture and browser
checks with the pinned font/Python inputs. The existing HarfBuzz, bare-runtime,
seek, motion and readability gates remain in `test/lettering-outlines.test.ts`.

The cost baseline was regenerated from a separate, unmodified main checkout,
then compared with all 26 PR outputs. Both page bytes and complete receipt hashes
match; the baseline was not generated by blessing PR outputs.

## Remaining limits

Awaiting a nested `Scene.run()` with a **different** lettering provider, including
an ordinary child inside a requested parent, remains unsupported and can deadlock.
Same-provider nesting and independent overlapping renders are supported and tested.
Render foreign-provider child scenes independently before composing their output.
Supporting arbitrary cross-provider nesting requires an execution-context design
that also preserves concurrent browser render isolation.

Bidi isolate controls and independently styling a character inside a ligature or
conjunct remain outside this feature. Select the whole source cluster for styling.
These limits are stated in `docs/LETTERING.md`; this audit does not claim broader
script or concurrency support than the tested paths.
