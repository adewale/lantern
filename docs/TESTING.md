# Testing Rayner

Run `npm run check` and `npm test` on Node 24 or later. `npm run test:full` increases generated-case counts. `npm run test:embeds` enables the real Chromium reader tests; set `CHROMIUM_EXECUTABLE_PATH` when Chromium is installed outside Playwright's cache. Lettering capture tests additionally need the pinned fonts and Python requirements described in [LETTERING.md](LETTERING.md). A skipped optional check supplies no pass evidence.

The suite uses fast-check for generated inputs and shrinking. `test/lib/pbt.ts` owns the seed and run-count policy. Generated tests complement the checked-in upstream vectors, Manim/raster references, browser integration and installed-package checks. These boundaries catch different failures; agreement between two calls to the same implementation is a weak substitute for an independent expected value.

The [2026-10 test audit](evidence/test-audit/README.md) accounts for all 679 original test declarations in 68 files. It records retained contracts, strengthened assertions, named consolidation keepers and remaining gaps. It applies OpenClaw's [test-audit workflow](https://github.com/openclaw/openclaw/tree/main/.agents/skills/test-audit) and Hegel's [property-testing and review guidance](https://github.com/hegeldev/hegel-skill) with Rayner's existing fast-check runner.

When changing tests, compare their proof before comparing their count. Check both acceptance and rejection, exact endpoint values and state transitions. Validate an important repaired assertion by deliberately breaking its producer, then restore the source. Keep optional integration results separate from pure property results. [test/AGENTS.md](../test/AGENTS.md) records the ownership rules from this audit.

The [upstream backport audit](evidence/upstream-backport/README.md) follows the remaining constructor, admission, runtime-input and layout gaps. Repeatable frames and matching snapshots can preserve a consistently wrong result. New laws therefore pin absolute constructor origins, visible identity/order, accepted runtime values, parsed XML data and independent DOM record updates. Visual review remains necessary: neither a geometric verifier nor a caption string can establish that an arbitrary scene tells its story.

`npm run demos:check` builds and checks the catalog. `npm run demos:review` then serves that exact output and visits every resting step of every settings case at 390 and 1180 pixels. It rejects stale build inputs and incomplete case inventories. Each width opens fresh; subsequent steps use the reader controls and wait for the matching ready event. The receipt counts every step/width row, and screenshots preserve each opening.

The story review checks declared subjects and fresh helper emphasis, falling back to changed artwork when neither exists, against actual SVG paths, computed paint, native bounds and clips at each close-up stop. Independent caption claims additionally name important subjects and opening requirements, including the OAuth attack arrows and WCAG Focus Visible criterion. Named subjects must be complete. Helper-highlighted route shapes may enter an authored viewport; their labels must remain whole and every highlighted subject must contribute visible ink. Explicit arrow claims remain whole. Incidental context may pass through an authored viewport; its expected visible portion comes from the source frame and must be reachable in actually painted views. A caption over unchanged artwork must declare a subject. Rectangle-union properties use an independent integer-cell oracle; browser controls reject missing, transparent, clipped and selectively hidden subjects.

The [story coverage audit](evidence/story-coverage/README.md) records the new owners and failing controls. These checks do not infer arbitrary caption meaning or prove that every possible overlap is harmless. Keep the imported/native route-collision checks, wording/value assertions, raster references, motion, transport, keyboard, touch and narrow-phone tests.

CI separates catalog generation from three all-step story jobs and retains the exact build and review artifacts. The final `story` check requires all three matching parts and validates the complete case/step/width inventory against built descriptions. It runs after failed dependencies and fails explicitly rather than being skipped. Use `npm run demos:review -- --shard N/3` for each part, then `node tools/explain-review-merge.ts` to reproduce the combined check. At the time of this audit, GitHub rejects dispatches with “Actions has been disabled for this repository” (422); the session credential cannot change Actions permissions (403). An owner must enable Actions in repository settings and require the `check`, `catalog`, `story` and compatibility checks. Local results do not establish hosted enforcement.
